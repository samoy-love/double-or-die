# Схема словаря строк

Человекочитаемое описание `content/strings.json`. Машинная проверка живёт в
`scripts/build-content.ts` (Zod) и валит сборку: этот файл её объясняет, а не
дублирует. Разошлись — прав генератор, а расхождение чинится здесь.

Файл — источник правды по каждой букве, которую видит игрок. Из него
собирается модуль `packages/client/src/strings.generated.ts` (`npm run
content`), и `npm run content -- --check` в CI ловит расхождение. Клиент
читает только сгенерированный модуль: ключи в нём типизированы, поэтому опечатка
в ключе — ошибка компиляции, а не пустое место на экране.

Обратная сторона того же правила — линтер `npm run check:i18n`: видимая строка,
вписанная в код мимо словаря, валит проверку ([UX §8](../docs/UX.md)).

## Корень

| Поле        | Тип    | Обяз. | Значение                                         |
| ----------- | ------ | ----- | ------------------------------------------------ |
| `$schema`   | строка | нет   | ссылка на этот файл                              |
| `version`   | `1`    | да    | версия формата словаря                           |
| `languages` | объект | да    | язык → таблица «ключ → строка»; ключи `ru`, `en` |

Языков ровно два и оба обязательны ([UX §8](../docs/UX.md)): русский —
исходник, английский — первый перевод. Остальные шесть приезжают в 0.12.0
и добавляются сюда же новым ключом верхнего уровня.

**Языки хранятся отдельными таблицами, а не по строке на ключ.** Переводчик
работает с языком целиком, ему нужен свой связный текст, а не колонка в чужой
таблице. Плата за это — риск забыть ключ в одном из языков, и ровно её
закрывают проверка паритета в генераторе и тест `tests/i18n.test.ts`.

## Ключ

`^[a-z][a-z0-9_]*(\.[a-z0-9_]+)+$` — точки делят область, точное место и
номер: `ace.bark.yawn.2`, `bet.no_damage.name`, `overlay.paused`.

Области сегодня: `bet` (имена пари), `ace` (реплики Туза), `settlement`
(экран расчёта), `overlay` (плашки поверх кадра), `error` (то, что игрок
видит вместо игры).

## Строка

Непустая, без переводов строки: перенос — забота раскладки, а не словаря.
Строка, разбитая `\n` в данных, ломается на первом же языке с другой длиной
слов.

### Подстановки

`{имя}` подставляется в рантайме: `t('overlay.paused')` без аргументов,
`t('overlay.dropped', { count })` — с ними. Имя внутри фигурных скобок —
`[a-z][a-zA-Z0-9]*`.

**Набор подстановок обязан совпадать во всех языках.** Перевод, потерявший
`{seed}`, оставляет игрока без номера сида в баг-репорте, и заметить это можно
только на том языке, на котором никто не играл.

Порядок подстановок в строке при этом свободен — в этом и смысл именованных
подстановок вместо позиционных.

## Что проверяет генератор сверх типов

- набор ключей во всех языках одинаков — ни пропущенных, ни лишних;
- ключ подходит под шаблон, строка непуста и без переводов строки;
- набор имён подстановок в строке одинаков во всех языках;
- `bet.<id>.name` есть ровно у тех `id`, что лежат в `content/bets.json`;
- русское `bet.<id>.name` не длиннее 28 знаков — условие на карте
  ([GLOSSARY, п. 7](../docs/GLOSSARY.md)); английское держится в тех же 28,
  чтобы макет не пришлось перекраивать под первый же перевод.

## Чего в файле не бывает

- **Разметки и HTML.** Строка уходит в текстовый батчер WebGL, тегов там нет.
- **Склеек из кусков.** «Осталось» + число + «секунд» — это три языка из
  четырёх, где так не говорят. Целая фраза с подстановкой или ничего.
- **Родовых форм в репликах Туза** ([GLOSSARY, п. 6](../docs/GLOSSARY.md)).
  Проверяется вычиткой, а не машиной: «соскочил» грамматически безупречно и
  ловится только глазами.
- **Отладочных сообщений.** Текст, который видит разработчик в консоли или в
  `throw`, живёт в коде и не переводится: переводить его — значит платить за
  семь языков там, где читателей двое.
