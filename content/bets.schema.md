# Схема каталога пари

Человекочитаемое описание `content/bets.json`. Машинная проверка живёт в
`scripts/build-content.ts` (Zod) и валит сборку: этот файл её объясняет, а не
дублирует. Разошлись — прав генератор, а расхождение чинится здесь.

Файл — источник правды по пари. Его правит балансировщик, его прочитает
редактор в админке, он же уедет в remote config. Ядро симуляции читать файлов
не умеет и не будет, поэтому те же числа попадают к нему готовым модулем
`packages/sim/src/bets.generated.ts` — его собирает `npm run content`, и
`npm run content -- --check` в CI ловит расхождение.

## Корень

| Поле      | Тип             | Обяз. | Значение                                        |
| --------- | --------------- | ----- | ----------------------------------------------- |
| `$schema` | строка          | нет   | ссылка на этот файл                             |
| `version` | `1`             | да    | версия формата каталога                         |
| `bets`    | массив объектов | да    | сами пари, минимум одно; порядок задаёт `BetId` |

**Порядок элементов значим.** Номер пари в массиве становится значением
`BetId` в ядре и номером бита в масках конфликтов. Новое пари дописывается в
конец; перестановка молча переназначит конфликты и сломает golden-реплеи.

## Пари

| Поле             | Тип              | Обяз.   | Ограничения                                                                |
| ---------------- | ---------------- | ------- | -------------------------------------------------------------------------- |
| `id`             | строка           | да      | `^[a-z][a-z0-9_]*$`, уникален; совпадает с хуком детекции                  |
| `name`           | строка           | да      | 1–28 знаков — условие на карте не длиннее (GLOSSARY, п. 7)                 |
| `category`       | перечисление     | да      | `style` · `tempo` · `space` · `greed` · `tricks` · `silly`                 |
| `multiplier`     | число            | да      | 1.1–10; в ядро уезжает в Q16.16                                            |
| `progress`       | перечисление     | да      | `time` · `counter` · `threat`                                              |
| `limitTicks`     | целое > 0        | условно | только и обязательно при `progress: "time"`                                |
| `target`         | целое > 0        | условно | только и обязательно при `progress: "counter"`                             |
| `conflicts`      | массив `id`      | да      | существующие пари, конфликт обязан быть взаимным                           |
| `excludeSchemes` | массив схем      | нет     | `gamepad` · `keyboard` · `touch`; без повторов и не все сразу              |
| `excludeCurses`  | массив проклятий | нет     | `blood`/`hustle`/`leadfeet`/`frozen`/`blackout`/`commission`; без повторов |

### `progress` — как считается доля пройденного под риском пути `q`

Значение `q` из [ECONOMY §9А](../docs/ECONOMY.md) определяет выплату за
«Забрать» и глубину near-miss.

- `time` — доля прошедшего времени от `limitTicks`. Темповые пари.
- `counter` — выполнено делить на `target`. Счётчиковые.
- `threat` — доля зачищенного бюджета угрозы комнаты, считая от момента
  взятия. Удержания и пространственные.

### `conflicts` — матрица конфликтов

Перечисленные пари не выпадают вместе (GDD §9.5). Конфликт обязан быть
объявлен с обеих сторон: односторонний означает, что пара всё-таки выпадет
вместе — смотря какую вытянули первой. Генератор сворачивает список в битовую
маску, поэтому в ядре проверка стоит одно сравнение.

### `excludeSchemes` — матрица «пари × схема ввода»

Схемы ввода, на которых пари невыполнимо. Такое пари не выпадает игроку с
этой схемой вовсе: пари на контроль выстрелов бессмысленно на таче с
автоогнём. Общая карта отбраковывается, если пари невыполнимо хоть у кого-то
за столом — гонка за карту, которую половина стола отыграть не может, честной
не бывает.

Поле необязательное: у большинства пари исключений нет, и пустой массив в
каждой записи был бы шумом. Исключить пари на всех схемах разом нельзя — это
не настройка, а вычёркивание пари из каталога окольным путём.

### `excludeCurses` — матрица «пари × проклятие»

Проклятия, при которых пари не выпадает и не лежит на арене (GDD §9.5, §11).
Ось нужна там, где активное проклятие либо делает условие пари бесплатным
(запрещённое им действие и так недоступно — «Свинцовые ноги» отключают рывок,
поэтому «Без рывка» перестаёт быть риском), либо портит его случайностью, не
зависящей от решений игрока («Заморозка» блокирует подбор фишек, пока жив
помеченный враг, — «Собери все фишки» тогда выполняется или срывается не по
тому, как играл игрок). Проверяется тем же кодом, что схемы ввода: активная
проклятая комната читается из `Meta.Curse`/`Meta.CurseRoom`, маска — один
бит на проклятие.

Поле необязательное, без повторов; в отличие от `excludeSchemes`, исключать
пари сразу на всех проклятиях можно — проклятие ровно одно за раз (§11 п.1), и
такая запись просто не даёт пари выпасть в проклятой комнате вовсе.

## Что проверяет генератор сверх типов

- идентификаторы не повторяются;
- конфликт ссылается на существующее пари и объявлен с обеих сторон;
- `limitTicks` есть тогда и только тогда, когда пари темповое;
- `target` есть тогда и только тогда, когда пари счётчиковое;
- схема ввода не перечислена в исключениях дважды и исключены не все схемы;
- проклятие не перечислено в исключениях дважды.

## Чего в файле не бывает

- **Секунд.** Время только в тиках: секунда в данных симуляции — это готовый
  десинк между 60 и 144 Гц.
- **Функций и выражений.** Пари — данные; логика, записанная в данных, не
  переживёт ни валидацию, ни remote config.
- **Этажных множителей.** `multiplier` пока каталожный; этажный приезжает в
  0.4.0 вместе с этажами ([ECONOMY §2](../docs/ECONOMY.md)).
