# Схема каталога апгрейдов

Человекочитаемое описание `content/upgrades.json`. Машинная проверка живёт в
`scripts/build-content.ts` (Zod) и валит сборку: этот файл её объясняет, а не
дублирует. Разошлись — прав генератор, а расхождение чинится здесь.

Файл — источник правды по тому, чем торгует Лавка. Его правит балансировщик,
его прочитает редактор в админке, он же уедет в remote config. Ядро симуляции
читать файлов не умеет и не будет, поэтому те же числа попадают к нему готовым
модулем `packages/sim/src/upgrades.generated.ts` — его собирает
`npm run content`, а `npm run content -- --check` в CI ловит расхождение.

## Корень

| Поле       | Тип             | Обяз. | Значение                                                |
| ---------- | --------------- | ----- | ------------------------------------------------------- |
| `$schema`  | строка          | нет   | ссылка на этот файл                                     |
| `version`  | `1`             | да    | версия формата каталога                                 |
| `upgrades` | массив объектов | да    | сами апгрейды, минимум один; порядок задаёт `UpgradeId` |

**Порядок элементов значим.** Номер апгрейда в массиве становится значением
`UpgradeId` в ядре и уезжает в слоты купленного (`pUpgrades`) со сдвигом на
единицу. Новый апгрейд дописывается в конец; перестановка молча переназначит
уже купленное и сломает golden-реплеи.

## Апгрейд

| Поле     | Тип          | Обяз. | Ограничения                                                        |
| -------- | ------------ | ----- | ------------------------------------------------------------------ |
| `id`     | строка       | да    | `^[a-z][a-z0-9_]*$`, уникален                                      |
| `name`   | строка       | да    | 1–28 знаков; служебное имя для отчётов, на экран идёт словарь      |
| `base`   | целое > 0    | да    | базовая цена, этаж первый ([ECONOMY §5](../docs/ECONOMY.md))       |
| `effect` | перечисление | да    | `damage` · `heart` · `dash_cooldown` · `magnet` · `drop` · `speed` |
| `value`  | целое > 0    | да    | величина эффекта, смысл зависит от `effect` (см. ниже)             |

### `base` — цена первого этажа

Цена на этаже `F` считается ядром как `base × 1.5^(F−1)` с усечением вниз
([ECONOMY §5](../docs/ECONOMY.md)). Сама степень живёт в симуляционном
конфиге (`UPGRADE.priceGrowth*`), потому что это правило игры, а не свойство
конкретного товара.

**Среднее по каталогу обязано быть 45.** Из него посчитана вся строка «Апгрейд
(средний)» в таблице расходов, а из неё — профили игрока: каталог, съехавший
со среднего, делает посчитанным не ту игру. Разъехавшееся среднее ловит тест,
а не совесть.

### `effect` — что именно меняется

Каждый эффект встречается в каталоге **ровно один раз**: два апгрейда на одну
величину складывались бы в разгон, которого в экономике нет, и «без повторов
уже купленного» перестало бы что-либо значить.

| `effect`        | Что меняет           | Смысл `value`                              |
| --------------- | -------------------- | ------------------------------------------ |
| `damage`        | урон пули            | процент от базового урона                  |
| `heart`         | запас сердец         | сколько сердец добавить, потолок в конфиге |
| `dash_cooldown` | откат рывка          | процент от базового отката                 |
| `magnet`        | радиус подбора фишек | радиус в единицах арены                    |
| `drop`          | шанс выпадения фишки | процент от базового шанса                  |
| `speed`         | скорость бега        | процент от базовой скорости                |

Проценты считаются целыми и усекаются вниз: здоровье врагов и шанс дропа —
целые числа, и дробный остаток ядру девать некуда.

**Поэтому процент обязан делиться нацело — усечение дороже 1% запрещено.**
Правило машинное, и оно родилось из потери: «+25%» от урона 10 давало 12.5,
ядро оставляло 12, и апгрейд молча стоил на 4% меньше обещанного. Проверяется
тестом на весь каталог сразу, а не глазами при правке одного товара — разъехаться
имеет право любой процент, а заметен разъезд только в отчёте балансировщика.

Отсюда числа, выглядящие подобранными: `120`, а не `125`, и `148`, а не `150`.
Они и подобраны — под делимость базы, чтобы обещанное на витрине совпало с
выданным в бою.

## Чего в файле не бывает

- **Секунд.** Время только в тиках: секунда в данных симуляции — это готовый
  десинк между 60 и 144 Гц. Откат рывка задан процентом, а не длительностью,
  ровно поэтому.
- **Функций и выражений.** Апгрейд — данные; логика, записанная в данных, не
  переживёт ни валидацию, ни remote config.
- **Видимого игроку текста.** Имя на экране приезжает из словаря по ключу
  `upgrade.<id>.name` ([content/strings.schema.md](strings.schema.md)); `name`
  здесь служебный и не переводится.
- **Ставочной ветки.** Страховка, На кураже, Шулер и остальные пять
  продаются с 0.6.0 вместе с глубиной ставок ([ECONOMY §5](../docs/ECONOMY.md)).
