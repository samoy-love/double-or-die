# Соглашения репозитория

Правила одинаковы во всех проектах samoy.love. Файл лежит в корне каждого
репозитория — если правите его, правьте везде.

## Документация проекта — читать до задачи

Этот репозиторий отличается от остальных: у игры есть **проработанная
стратегия в `docs/`**, и она первична по отношению к любой отдельной задаче.

**Перед любой работой читаем то, чего касается задача.** Не «если непонятно», а
всегда. Правки, сделанные мимо стратегии, дороже несделанных: игра держится на
нескольких решениях, которые невозможно поменять задним числом
(детерминизм ядра, отсутствие экрана ставок, положительное матожидание пари),
и код, разошедшийся с ними, придётся переписывать целиком.

| Файл                                    | Когда обязателен                                          |
| --------------------------------------- | --------------------------------------------------------- |
| `docs/GLOSSARY.md`                      | всегда — источник истины по именам                        |
| `docs/ROADMAP.md`                       | всегда — что входит в текущую версию и какие у неё ворота |
| `docs/GDD.md`                           | любая правка механик, врагов, интерфейса                  |
| `docs/TECH.md`                          | архитектура, сеть, сборка, детерминизм                    |
| `docs/ECONOMY.md`, `docs/DIFFICULTY.md` | любое изменение чисел                                     |
| `docs/DEVLOOP.md`                       | тесты, отладка, инструменты агента                        |
| `docs/UX.md`                            | управление, HUD, доступность                              |
| `docs/SECURITY.md`, `docs/OPS.md`       | бэкенд, телеметрия, античит                               |
| `docs/PRODUCTION.md`                    | визуал, аудио, ассеты                                     |
| `docs/BUSINESS.md`, `docs/REVIEW.md`    | сроки, площадки, риски                                    |

**Документация обязана оставаться актуальной.** Изменилось поведение — правка
в `docs/` входит в тот же PR, что и код. Расхождение кода и документа — дефект
той же тяжести, что сломанный тест.

**Просьба владельца изменить решение — это правка во всех файлах, где оно
описано.** Одно решение живёт в нескольких документах, и обновить один — значит
оставить противоречие, которое всплывёт через месяц и будет стоить дороже.
Порядок: найти все упоминания (`GLOSSARY` первым), обновить каждое, проверить,
что не осталось следов старого.

**Устаревшему в `docs/` не место.** Это рабочая база знаний, а не летопись:
никаких «раньше было так, потом решили иначе». Решение записывается в текущем
виде, обоснование остаётся только там, где защищает от повторной ошибки.

## Коммиты

**В коммитах не должно быть упоминаний ИИ.** Никаких трейлеров
`Co-Authored-By: Claude`, никаких «generated with» в сообщениях коммитов,
описаниях PR и релизных заметках. Это личные проекты и публичное портфолио —
авторство принадлежит владельцу репозитория.

Сообщения — на русском, повелительным наклонением, первая строка до 72
символов и без точки. Тело объясняет **почему**, а не пересказывает диф.

Первая строка коммита — это и есть строка релиза. Сквош-мерж схлопывает ветку
в один коммит, тема которого — заголовок PR, и именно её бот кладёт в чат при
выкатке. Больше о релизе читатель не увидит ничего, поэтому заголовок PR
подчиняется тем же правилам, что и тема коммита.

Тема отвечает, **что изменилось в проекте**, а не что изменилось в коде:
читатель в чате не видел ни ветки, ни дифа, ни задачи.

```
плохо   Заменить || true на разбор ответа в notify()
хорошо  Не выдавать недоставленное уведомление за успех

плохо   Убрать таймаут из HttpClientProvider
хорошо  Починить обрыв скачивания больших файлов

плохо   Правки после ревью
хорошо  Считать пропавший файл ошибкой обновления
```

Потолок темы — 120 символов: что длиннее, режется многоточием посреди фразы.
72 символа выше — норма, 120 — граница. Одна мысль — один коммит.

Тема читается в отрыве от всего: «Поправить как обсуждали», «Мелкие правки»,
«Фикс» в чате не значат ничего.

Тема не начинается с `WIP`, `fixup!`, `squash!`, `bump`, `deps: bump` и не
сводится к «Поднять версию» — генератор списка считает такое шумом и **молча
выбрасывает**. Настоящее изменение, названное так, из релиза исчезнет.

Темы коммитов **публичны**: они уезжают в `version.json`, который раздаётся
по HTTP. Ни секретов, ни внутренних адресов, ни подробностей инцидента в теме.

Правило проверяется машиной, а не только совестью: задача `commits` в CI
валит сборку на любом упоминании ИИ. Локально то же самое ловит хук — он
включается один раз на репозиторий, клоном не переносится:

```bash
git config core.hooksPath .githooks
```

Не коммитим чужие изменения: перед коммитом смотрим `git status` и добавляем
только свои файлы. `git add -A` в грязном дереве запрещён.

## Ветки

Работа идёт в ветке, `main` защищён. Мерж — после зелёного CI.
Каждый мерж в `main` уезжает на прод, поэтому `main` обязан быть выкатываемым
в любой момент.

## Версии

Релиз без версии не едет. Версия проставляется до коммита, растёт явно и
проверяется после выкатки: `/version.json` на проде должен совпасть с тем,
что собрали. «Зелёный деплой со старыми файлами» ловится именно здесь.

Версии игры идут по плану из `docs/ROADMAP.md`. Минорная версия закрывается
только после прохождения её **ворот** — критерия, записанного в плане.
Ворота 0.2.0 («в бой приятно играть пять минут без единой ставки») не
смягчаются ни при каких обстоятельствах.

## Выкатка

Единственный путь — [deploy-kit](https://github.com/tr0llex/deploy-kit).
Своих скриптов деплоя в проектах нет.

```bash
dk                 # что сейчас на проде
dk deploy          # выкатить цели этого проекта
dk rollback <цель> # откатить
```

Локальная выкатка и CI идут одним и тем же путём: одно описание цели
(`.deploy-kit/*.env`) и один `release.sh` на сервере.

Цели этого проекта: `game` (прод, `die.samoy.love`) и `dev`
(nightly, `dev.die.samoy.love`).

## nginx

Конфигурация живёт **только** в `deploy-kit/nginx/`. В проектных репозиториях
копий не держим. Правки применяются через `server/nginx-apply.sh`, руками в
`/etc/nginx` не ходим.

## Тесты

Тесты — гейт, а не украшение: красный прогон останавливает выкатку.

Специфика игры: помимо обычных тестов гейтом являются **golden-реплеи** —
записанные логи инпутов с эталонным хешем состояния. Они ловят слом
детерминизма, самый опасный класс багов в этом проекте, и прогоняются на трёх
операционных системах. Реплей привязан к версии симуляционного конфига;
молчаливое обновление эталонных хешей запрещено — ре-бейзлайн делается
осознанно и попадает в заметки версии.

Новая механика без сценария — незакрытая работа. Сценарии и golden-реплеи
только накапливаются, никогда не удаляются.

## Структура

```
README.md          русский, единственный markdown в корне вместе с
README.en.md       английской версией и этим файлом
docs/              стратегия проекта: дизайн, техника, экономика, план
packages/          монорепозиторий игры
  sim/             ядро симуляции: чистый TS, ноль зависимостей
  shared/          типы, схемы, протокол
  client/          рендер, звук, ввод, интерфейс
  tools/           headless-раннер, балансировщик, сценарии
content/           данные: пари, враги, апгрейды, барки (JSON + схема)
tests/             сценарии и golden-реплеи
.deploy-kit/       описания целей выкатки
.github/workflows/ вызовы переиспользуемых workflow из deploy-kit
.claude/           конфигурация запуска для агента
```

Русский — основной язык: README.md русский, English идёт второй версией.

Журналы изменений в README не ведём — для этого есть история git.
Планы и идеи — в issues, а не в файлах.
