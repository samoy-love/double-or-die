# Double or Die — безопасность и античит

_Модель угроз, защита клиента и бэкенда, честные границы античита._

---

## 1. Что мы защищаем и от кого

| Актив                     | Угроза                       | Насколько важно                                |
| ------------------------- | ---------------------------- | ---------------------------------------------- |
| Данные игроков            | утечка, деанонимизация       | **критично** — юридически и репутационно       |
| Достоверность лидербордов | накрутка, подделка рекордов  | высоко — иначе таблицы бессмысленны            |
| Игроки друг от друга      | раскрытие IP, DDoS, троллинг | **высоко** — недооценённая угроза в P2P        |
| Балансная аналитика       | отравление телеметрии        | средне — мы принимаем по ней решения           |
| Бэкенд                    | DoS, порча конфига           | средне — игра работает и без него              |
| Админ-доступ              | захват удалённого конфига    | **критично** — один конфиг ломает всех игроков |
| Сохранение игрока         | правка мета-прогресса        | **не защищаем** — см. §6                       |

**Чего мы принципиально не делаем:** ядерного античита с драйвером. Для казуальной кооп-игры за $10 это неоправданно инвазивно, дорого, ломает Linux и Steam Deck и отпугивает аудиторию. Наша цель — «лидерборды достоверны, а читерство не тривиально», а не «непробиваемо».

## 2. Клиент

### 2.1 Отладочный интерфейс — вырезать из продакшена

`window.__DOD__` даёт полный контроль над симуляцией: выдать фишки, телепортироваться, подменить конфиг. **В продакшен-сборку он не попадает вообще** — исключается на этапе сборки флагом, а не проверкой в рантайме, иначе его достанут из бандла.

```
DEV / staging  → __DOD__ включён, баннер «DEBUG» в углу
production     → код физически отсутствует в бандле
```

CI-проверка функциональная, не текстовая (grep по минифицированному коду ничего не доказывает и шумит на легитимных словах): прод-бандл загружается headless, утверждается `window.__DOD__ === undefined`, а debug-модуль отсутствует в графе модулей бандлера. Несоблюдение — красная сборка.

### 2.2 Electron: обязательный чеклист

Электрон по умолчанию небезопасен. Настройки не обсуждаются:

```js
webPreferences: {
  contextIsolation: true,      // обязательно
  nodeIntegration: false,      // обязательно
  sandbox: true,
  webSecurity: true,
  allowRunningInsecureContent: false
}
```

- Preload-скрипт публикует **минимальный** API (сохранения, Steam, телеметрия) — не `require`, не файловую систему целиком.
- Каждое IPC-сообщение валидируется по схеме; канал с непредусмотренным именем игнорируется.
- CSP в самой странице, `default-src 'self'`, без `unsafe-eval`.
- Никакой загрузки удалённого контента в окно игры. Навигация запрещена (`will-navigate` + `setWindowOpenHandler` → deny); внешние ссылки — только через валидацию URL (http/https-белый список) перед `shell.openExternal`, иначе крафтовая ссылка открывает `file://`.
- Electron Fuses: `runAsNode` и `nodeCliInspect` выключены в собранном бинарнике.
- Связка `sandbox: true` + нативный `steamworks.js` в preload — потенциальный конфликт, спайк перед 0.10.0.
- Версия Electron обновляется по расписанию и **немедленно при security-релизе Chromium**.

### 2.3 Веб-сборка

CSP-заголовки, никакого `eval`, целостность подключаемых ресурсов. Ключей и секретов в бандле нет никогда — всё, что попало в клиент, считается публичным.

### 2.4 Крэш-репорты

Перед отправкой в Sentry вычищаются пути пользователя, имена файлов из домашней директории и любые строки, похожие на персональные данные. `beforeSend` — обязательный фильтр, а не опция.

## 3. Бэкенд

### 3.1 Приём телеметрии

Открытый endpoint без аутентификации — значит, его будут заливать мусором.

| Защита                        | Параметр                                                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Ограничение размера тела      | 64 КБ, больше — отказ до разбора                                                                                  |
| Rate limit                    | по IP/подсети (`pid` генерируется клиентом, ротируется бесплатно и защитой не является — им только дедуплицируем) |
| Валидация схемы               | строгая, лишние поля отбрасываются, невалидное событие не пишется                                                 |
| Защита от распаковочной бомбы | лимит на размер после декомпрессии                                                                                |
| Метрика отказов               | всплеск отказов сам по себе сигнал атаки                                                                          |

**Ключевой принцип:** телеметрия **никогда** не является источником истины для чего-либо, влияющего на игрока. Она советует, что чинить в балансе; она не выдаёт награды, не влияет на лидерборды и не управляет доступом. Поэтому отравление аналитики — неприятность, а не катастрофа. Аномальные всплески дополнительно отсекаются при агрегации (усечённые средние вместо обычных).

### 3.2 Валидация реплеев — самый опасный endpoint

Это **исполнение пользовательского ввода на нашем сервере**. Требования жёсткие:

- **Аутентификация и квота — до очереди:** лог принимается только с валидным Steam-тикетом и в пределах суточной квоты на аккаунт. Без этого endpoint — усилитель DoS: цена атакующего копеечная, наша — полная ресимуляция.
- Максимальный размер лога инпутов; превышение — отказ без разбора.
- **Жёсткий лимит тиков** симуляции: забег физически не может длиться дольше N — иначе крафтовый лог заставит сервер считать вечно.
- Валидация — в отдельном процессе (replay-worker) на VPS: очередь в SQLite, timeout и пониженный приоритет, чтобы не душить основной сервис. Скорость ресимуляции против реального времени — спайк до 0.11.0.
- Симуляция запускается **той же детерминированной сборкой**, что у клиента, с серверной версией конфига за нужную дату — клиентский конфиг не принимается вообще.

### 3.3 Аутентификация

Лидерборды принимают результат только с валидным Steam-тикетом, проверенным через Steam Web API на сервере. Иначе тривиально отправить чужой реплей под своим именем или наоборот.

Анонимный `pid` из телеметрии **не связывается** со Steam ID — это разные хранилища с разными сроками жизни.

### 3.4 Админ-панель

Единственная точка, где компрометация ломает всех игроков сразу.

- Админка не выставляется в публичный интернет: доступ через Tailscale/WireGuard (предпочтительно) или Basic-auth + TOTP за nginx на VPS.
- Роли `viewer` / `designer` / `admin`; редактировать конфиг может не каждый.
- **Аудит-лог append-only с механизмом, а не обещанием:** отдельная таблица без UPDATE/DELETE у роли приложения + litestream-копия off-site, недоступная с VPS на перезапись. Кто, что, когда, откуда.
- Любое изменение конфига проходит серверную валидацию схемы — сломанный конфиг не должен попасть к клиентам физически.
- Раскат по процентам — только для прикладного класса конфига; симуляционный выкатывается целиком ([TECH.md §8.3](TECH.md)), и интерфейс админки физически не даёт раскатать его частично. Откат мгновенный; на клиенте всегда есть встроенный резервный конфиг.

## 4. Мультиплеер

### 4.1 IP-адреса — недооценённая угроза

Прямое P2P-соединение раскрывает IP-адреса игроков друг другу. В сетевых играх это регулярно приводит к DDoS-атакам на победителя. Мы это не допускаем:

| Сборка          | Решение                                                                                                                                                                                                                                                                                                               |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Steam           | **Steam Networking Sockets** — трафик идёт через релеи Valve, реальный IP не виден пирам. Бесплатно и по умолчанию                                                                                                                                                                                                    |
| Веб / мобильные | WebRTC **только через TURN-релей** (coturn на VPS); прямое соединение с раскрытием адреса отключено, даже ценой лишних 30 мс. Креды TURN — короткоживущие HMAC (ephemeral, RFC 8489), выдаются бэкендом только аутентифицированным клиентам — иначе украденные креды превращают релей в бесплатный прокси за наш счёт |

Это не настройка производительности, а требование безопасности.

### 4.2 Недоверенный пир

Все сетевые сообщения приходят от потенциально злонамеренного клиента:

- Каждый пакет валидируется по схеме и границам; неожиданный формат — разрыв соединения, а не исключение в игровом цикле.
- Инпут-кадры проверяются на диапазон (вектор нормализован, номер тика в разумном окне) — иначе крафтовый инпут может вывести симуляцию за пределы массивов.
- Лимит частоты сообщений на пира.
- Флуд запросами на ресинк игнорируется: снимок состояния рассылается не чаще заданного интервала.
- У хоста есть кик; в публичных лобби — репорт и блок.

### 4.3 Совместимость версий как поверхность атаки

`PROTOCOL_VERSION` проверяется при рукопожатии до любого обмена данными. Клиент старой версии не «как-нибудь работает», а получает понятное сообщение — иначе несовместимость выглядит как десинк и маскирует настоящие проблемы.

## 5. Античит

### 5.1 Что нам даёт детерминизм бесплатно

| Атака                         | Почему не работает                                                                                   |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- |
| Подделка результата забега    | сервер переигрывает лог инпутов и сверяет хеш — соврать о результате невозможно                      |
| Ускорение игры (speedhack)    | время измеряется тиками симуляции, а не секундами; крутить клиент быстрее бессмысленно               |
| Правка памяти в кооп-лобби    | расхождение немедленно ловится сверкой хешей — **детекция десинков одновременно работает античитом** |
| Подмена remote config         | сервер валидирует реплей своей версией конфига, клиентская не принимается                            |
| Повтор чужого удачного реплея | привязка к Steam-тикету, одна попытка в дейли на аккаунт                                             |

Это редкий случай, когда архитектурное решение, принятое ради производительности и онлайна, закрывает большую часть читерства как побочный эффект.

### 5.2 Чего валидация реплеев НЕ ловит — и это честно

**Переигрывание лога доказывает, что инпуты дают заявленный результат. Оно не доказывает, что эти инпуты произвёл человек.**

Игрок может оффлайн, покадрово, за час собрать идеальный лог инпутов и отправить формально валидный «рекорд». Это классический tool-assisted speedrun, и от него детерминизм не защищает — наоборот, помогает.

Что с этим делаем соразмерно масштабу игры:

1. **Эвристики человечности** на логе: аналоговые стики без микродрожи, реакции стабильно быстрее 100 мс, мгновенные довороты прицела на точный угол, идеально одинаковые интервалы между действиями. Ни одна эвристика не является доказательством — все они лишь помечают запись.
2. **Ручная очередь разбора** для верхушки таблиц. Реплей можно просто посмотреть в админке ([OPS.md §6](OPS.md)) — подозрительный забег виден глазами за минуту.
3. **Две таблицы:** «проверенная» (прошла эвристики и разбор) и общая. Рекорд не удаляется молча, он переезжает.

**Осознанная позиция:** в казуальной кооп-игре ставки низкие. Тратить месяцы на борьбу с TAS-рекордами — плохая инвестиция; сделать так, чтобы обычный игрок не мог накрутить в две минуты, — достаточно.

### 5.3 Читерство в кооп и Versus

- **Кооп с друзьями:** доверяем. Модифицированный клиент вызовет десинк и вылетит сам.
- **Аимбот** десинка не вызывает — это формально легальный ввод. В PvE он вредит только удовольствию самого читера.
- **Versus онлайн** — единственное место, где аимбот реально вредит. Меры: анализ ввода на нечеловеческую точность, разделение таблиц по устройству ввода и приоритет лобби «только друзья». Честно: разделение по устройству — **UX-мера, не античит** (тип устройства декларирует клиент); дополнительно классифицируем по статистике самого лога (дискретность стика против мыши) — с теми же оговорками, что у эвристик §5.2. Результат матча при десинке не записывается без пост-валидации реплеев обеих сторон.
- **Глобальных соревновательных PvP-рейтингов не делаем.** Их невозможно защитить без ядерного античита, а без защиты они превращаются в витрину читеров.

## 6. Сохранения: не защищаем осознанно

Локальный сейв редактируется в блокноте. Мы **не пытаемся** этому мешать: обфускация и подписи в одиночной игре лишь создают иллюзию защиты и наказывают любопытных, ничего не давая взамен.

Из этого следует правило проектирования: **ничто ценное не должно опираться на сейв**. Лидерборды валидируются реплеем на сервере, мультиплеер — детерминизмом, награды не выдаются по содержимому сохранения. Игрок, выдавший себе все разблокировки, испортил игру только себе.

## 7. Цепочка поставок

- Lockfile обязателен, обновления зависимостей — отдельными коммитами с ревью.
- `npm audit` и проверка лицензий в CI, автоматические обновления безопасности.
- **У пакета `sim` ноль зависимостей** — самая критичная часть кода не имеет поверхности атаки через npm вовсе.
- Артефакты сборки подписываются; воспроизводимость проверяется в CI сборкой дважды и сравнением хешей.
- Секреты только в GitHub Secrets и `.env` на VPS, никогда в репозитории. Сканер секретов в pre-commit.
- **Чужие GitHub Actions пиннятся по полному SHA** с тегом в комментарии рядом (`actions/checkout@3d3c42e5… # v7.0.1`). Угроза именно в чужом коде: тег — подвижная ссылка, и его компрометация означает утечку секретов подписи из нашего пайплайна.
- **Исключение — переиспользуемые workflow из `tr0llex/deploy-kit`, они вызываются по ветке (`@main`) намеренно.** Это не чужой код: deploy-kit принадлежит тому же владельцу и является единственным путём выкатки во всех проектах samoy.love. Запиннить его по SHA значило бы завести столько же молча расходящихся деплоев, сколько репозиториев, — и чинить каждый по отдельности, узнавая о расхождении в момент неудачной выкатки. Правило записано так, чтобы исключение было названо: подразумеваемое, оно через полгода читается как недосмотр, и кто-нибудь «починит» его пиннингом.
- Обязательная 2FA на GitHub-аккаунте; ключ подписи Windows-сборок — не в общих секретах CI, а в отдельном хранилище.

## 9. Реагирование на инциденты

| Инцидент                       | Действие                                                                | Цель по времени                     |
| ------------------------------ | ----------------------------------------------------------------------- | ----------------------------------- |
| Сломанный конфиг у игроков     | откат конфига в админке                                                 | минуты                              |
| Критический баг в сборке       | откат билда в Steam на предыдущий, отзыв веб-версии                     | часы                                |
| Утечка админ-доступа           | отзыв ключей Tailscale/TOTP, ротация секретов VPS, разбор аудит-лога    | немедленно                          |
| Утечка данных игроков          | оценка объёма, уведомление регулятора и игроков в 72 часа (GDPR)        | немедленно                          |
| Потеря данных VPS              | восстановление из litestream-бэкапа; процедура отрепетирована до 0.11.0 | часы                                |
| Массовая накрутка таблицы      | заморозка таблицы, разбор реплеев, пересчёт                             | сутки                               |
| Уязвимость в Electron/Chromium | внеочередной патч рантайма                                              | по серьёзности, критические — сутки |

Публичный контакт для сообщений об уязвимостях (`security@`) и обещание не преследовать добросовестных исследователей — на странице игры и в репозитории.
