# dev-alpha

Внутренние версии. Играет только разработчик и агент.

## 0.1.0 «Скелет»

**Цель:** доказать детерминизм и дать агенту возможность управлять игрой без единого клика. Геймплея нет — вся ценность в фундаменте, который невозможно заложить позже.

### Репозиторий и окружение [Ф]

- Приватный репозиторий GitHub, работа через PR. **Защита ветки машиной не включена:** GitHub не даёт её приватным репозиториям без платного тарифа, поэтому правило держится дисциплиной и проверяется на ревью. Варианта два — оплатить тариф или открыть репозиторий; до тех пор это известная дыра, а не забытая строка
- Монорепозиторий: `packages/sim`, `shared`, `client`, `tools`
- Vite + TypeScript strict, ESLint, Prettier
- **Линтер границ модулей:** `sim` не импортирует ничего; `window`/`document`/`Math.random`/`Date.now` в `sim` — ошибка сборки
- Сканер секретов в `pre-commit`: приватные ключи, токены с узнаваемым префиксом и файлы окружения не уезжают в историю. Проверяются только добавляемые строки — хук, ругающийся на давно лежащий текст, отключают через неделю
- `.env` и `.env.*` в `.gitignore`. Образца `.env.example` нет намеренно: своих переменных окружения у игры сейчас нет вовсе, и пустой образец врал бы о наличии настроек
- `.claude/launch.json` — конфигурация запуска для агента
- CI: `lint → typecheck → unit → golden → build` на матрице win/mac/linux

### Ядро симуляции [Я]

- Fixed-point Q16.16: `add`, `sub`, `mul`, `div`, `sqrt`
- **`mul`/`div` через hi/lo-разбиение** — произведение двух Q16.16 не влезает в 53-битную мантиссу
- Таблицы `sin`/`cos` на 4096 значений с интерполяцией, `atan2`
- Анализ диапазонов величин, закреплённый тестом `tests/ranges.test.ts`. Вывод: **Q24.8 не нужен нигде**. Позиции и скорости лежат в Q16.16 с запасом, а квадраты позиций в него не помещаются в принципе — их считает `length()`, уходя в обычные числа
- RNG `xoshiro128**`, **семь независимых потоков**: `layout`, `waves`, `bets`, `cards`, `loot`, `shop`, `combat` ([TECH.md §2.3](TECH.md)). Последний обслуживает мелкую случайность боя — разброс выстрела, отскок фишки — и начинает работать вместе с боем в 0.2.0
- Фиксированный тик 60 Гц с аккумулятором, отвязанный от кадра
- Состояние SoA на типизированных массивах, предаллокация под потолки
- Снимок и восстановление состояния
- Хеш состояния FNV-1a
- `InputFrame` с 16-битной маской ([TECH.md §6](TECH.md))
- Запись и воспроизведение лога инпутов, RLE-сжатие
- Инварианты в dev-сборке (`[DOD:INVARIANT]`)

### Клиент [К]

- Рендер на Canvas 2D с пулами объектов. WebGL2 с батчингом — в 0.2.0, вместе с сочностью, ради которой он и нужен: тянуть тысячи частиц в 0.1.0 нечем и незачем, а интерфейс рассчитан на подмену бэкенда
- Интерполяция между тиками (поддержка 120/144 Гц бесплатно)
- **Палитра в одном модуле** — захардкоженный цвет в коде отрисовки ловится линтером
- Слой ввода: Gamepad API, клавиатура, мышь → нормализация в `InputFrame`
- Радиальная мёртвая зона 0.18, буфер ввода 6 кадров, coyote-время 4 кадра
- Игрок-квадрат: движение, рывок-заглушка
- Отладочный оверлей: FPS, номер тика, хеш состояния, версия сборки

### Доставка сборки [Ф]

- Версия и git-SHA зашиваются в билд, видны в оверлее и в баг-репортах
- Контент-хешированные имена файлов
- Service worker с фоновым обновлением. Из кеша берётся только то, у чего хеш содержимого в имени (`/assets/`); всё прочее — сеть вперёд, кеш запасным путём. Иначе закешированный `index.html` запирает игрока на старой версии навсегда, и перезагрузка не помогает
- **Проверка версии при запуске:** клиент сравнивает КОММИТ сборки с тем, что отдаёт манифест. Не строку версии: на проде манифест пишет deploy-kit, и его метка релиза не совпадает с нашей версией никогда
- Ненавязчивый индикатор «доступна новая версия», применение при следующей перезагрузке
- Предыдущая сборка остаётся доступной по адресу — механизм отката
- nginx на VPS раздаёт `dev.die.samoy.love` через deploy-kit: длинный кеш на хешированных файлах, `no-cache` на `index.html` и `no-store` на манифесте версии ([DEPLOY.md](DEPLOY.md))

> Без этого агент и разработчик будут ловить фантомные баги из устаревшего кеша, а версия в баг-репорте станет бессмысленной.

### Инструменты [И]

- Headless-раннер `npm run sim`: `--seed`, `--runs`, `--bot`, `--json`, `--out`, `--determinism-check`, `--replay`, `--assert-hash`, `--scenario`, `--golden`
- Перезапись эталонов только явным `--record-golden ... --rebaseline`: молчаливый ре-бейзлайн превращает golden-тест в подтверждение любого поведения
- Боты `idle` и `random`
- `window.__DOD__` — **только в dev-сборке**: `ready`, `newRun`, `tick`, `state`, `hash`, `events`, `input`, `perf`, `stable`
- Навигация по URL-параметрам: `seed`, `players`, `autopause`, `stable`, `debug`. **`debug=1` включает оверлей, а не `__DOD__`:** отладочный интерфейс даёт полный контроль над симуляцией и в релизе является читом, поэтому вырезается сборкой навсегда
- Протокол консоли `[DOD]` / `[DOD:ERROR]` / `[DOD:INVARIANT]` в одном модуле. Нарушенный инвариант останавливает цикл и печатает сид с тиком, но не бросает исключение наружу: упавший rAF унёс бы с собой рендер и отладочный интерфейс, и агент увидел бы застывшую картинку вместо причины
- Формат сценариев и раннер
- `npm run bench`, `npm run check`

### Тесты [Т]

- Юнит: fixed-point математика, RNG, границы диапазонов
- **20 golden-реплеев × 3 ОС**, сверка хеша каждые 600 тиков, составы 1–4 игрока
- Сценарии: формат, раннер и первые пять
- Отсутствие аллокаций: 10 000 тиков без роста кучи
- **Прод-бандл не содержит отладочного API** — функциональная проверка, не поиск по тексту
- Бенч ядра `npm run bench`: тик, хеш, снимок и восстановление с запасом к бюджету кадра. Нагрузочный бенч рендера (2000 частиц + 200 болванок) — в 0.2.0, вместе с частицами
- Линтер палитры: захардкоженный цвет вне `palette.ts` валит сборку

### Спайки

1. Fixed-point: hi/lo умножение и анализ диапазонов
2. Детерминизм: идентичные хеши на трёх ОС
3. ~~60 FPS на Steam Deck~~ — здесь мерить нечего, пока на экране четыре квадрата: замер на Canvas 2D ничего не скажет о WebGL2-рендере, ради которого он и затевается. Спайк живёт в процессном долге 0.2.0 и просрочен

- Рэгдолл-отброс с кувырком
- **Фотосенситивный порог сразу:** без полноэкранных строб, вспышки ≤3 Гц

### Аудио [К]

- Ноль ассетов — настройка правкой числа

### Тесты [Т]

- Автомат каждого врага: все переходы, длительность телеграфа
- Рывок: i-frames спасают от снаряда, кулдаун соблюдается
- **Достижимость безопасной точки** на каждом тике

### Процессный долг

Версия была закрыта и выпущена без трёх пунктов. Два из них закрыты в 0.4.0,
один остаётся; ниже фактическое состояние каждого. Формулировка «сделаем с этой
версии» здесь была бы враньём в свою пользу: документ пишется для себя
будущего, и невыполненное обязано выглядеть невыполненным.

| Пункт                                            | Состояние                                                                                                                                                                                          | Обязателен к                    |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| Постоянный плейтест                              | **закрыт в 0.4.0.** Владелец играет с друзьями регулярно, и это и есть тот канал, ради которого пункт заводился. Формального списка из пяти–десяти человек не будет: он описывал способ, а не цель | —                               |
| Первое внешнее арт-ревью                         | **закрыто в 0.4.0.** Проведено, и его результат — редизайн: новый визуальный язык (тёмная заливка, несущая обводка), типографика и все экраны забега                                               | —                               |
| Спайк «60 FPS на Steam Deck» (переехал из 0.1.0) | выполнен наполовину: в CI бежит прокси-замер в Chromium на раннере, и он ловит обвал цикла, но о железе Deck не говорит ничего — там программный растеризатор                                      | 0.5.0 — первый публичный выпуск |

**Чем теперь меряются человеческие ворота.** Пункт про канал исчез, а
измерение — нет: «>60% начинают второй забег» и «≥95% берут пари» по-прежнему
проверяются людьми. Носитель для этого уже есть — баг-репорт складывает
детерминированный реплей забега файлом ([DEVLOOP](DEVLOOP.md)), и присланная
запись переигрывается headless-раннером с любыми вопросами, включая те, что не
задавались в момент записи. Отличие от прежнего плана в том, что канал не
организуется отдельно, а совпадает с теми, с кем владелец и так играет.

## 0.3.0 «Ставка»

**Цель:** ставки живут внутри боя и ощущаются своим решением, а не заданием.

### Карты пари [Я]

- Карта как сущность симуляции: позиция, категория, владелец, оставшиеся тики
- Раскладка **`N` персональных + 2 общих**, разнесённо по арене
- Подбор **подтверждением кнопкой**, не наездом
- Детерминированное разрешение одновременного подбора
- Карта тает за 720 тиков, предупреждение за 180
- Подброс карты Крупье на половине зачищенной угрозы — чистая функция от состояния: точка считается от центра масс живых игроков
- **Крупье уходит с арены** через 3 с после подброса; выходов за комнату не больше двух, пауза между ними 6 с считается от ухода
- Лимит активных пари: 4 на игрока

### Механика ставок [Я]

- Шесть пари★: без урона, без рывка, быстрее 45 с, не заходи в красную зону, собери все фишки, подрывник
- **Прогресс `q`** для каждого пари ([ECONOMY.md §9А](ECONOMY.md))
- «Забрать»: `кон × (1 + q × (M−1)/2)`, командные не обналичиваются
- Аппетит: три тира, защёлка до следующего явного нажатия, сброс в «Скромно» на старте комнаты (свой экран двери — в 0.4.0)
- Кон списывается за каждую карту, не превышает кошелёк; забег начинается со **стартового капитала 30 фишек**, иначе кон `min(тир, кошелёк)` — ноль, и механика версии не включается ([ECONOMY §4](ECONOMY.md))
- Расчёт: выплата, провал, **near-miss**
- Матрица конфликтов пари и матрица «пари × схема ввода»: обе — данные каталога, схема ввода едет битами кадра **со сдвигом аппетита на единицу** ([TECH.md §6](TECH.md)). Схема не обходится и на вырожденном столе: выдавать нечего — карты не будет ([GDD §9.5](GDD.md))

### Крупье [К]

- Появление на арене, слой ниже боевых сущностей, полупрозрачность при перекрытии
- Телеграф подброса 0.5 с, без коллизии и уязвимости
- **Жесты:** зевает, аплодирует провалу, отворачивается на пороге куша, нервничает, показывает палец вниз, аплодирует стоя нелепой смерти ([GDD §17А](GDD.md)). Жест — часть состояния симуляции: реплей обязан его воспроизводить. Пороги разведены (75% — отворот, 90% — палец вниз и овация)
- **Выход «на настроение»:** событие, достойное реакции, приводит Крупье само — с тем же телеграфом, что у подброса. Событийные жесты зовут его, пассивные (зевок, отворот, суета) нет: они верны всё время, пока верно положение дел, и потратили бы единственный выход впустую ([GDD §17А](GDD.md))
- Дозировка: злорадство молчит, пока идёт серия смертей, и возвращается с новой комнатой
- Система контекстных барков: словарь и выбор реплики работают, текст в кадре приезжает со шрифтом в F2 ([PRODUCTION §4](PRODUCTION.md))

### Интерфейс [К]

- HUD активных пари с «дыханием» и растущей потенциальной выплатой
- Глиф «Забрать» рядом с кушем
- Карты: кремовая подложка, иконка категории, вертикальный луч; **подсветка карты под ногами** — масштаб, дыхание, кольцо цветом берущего и глиф кнопки по схеме ввода ([UX §4](UX.md))
- Луч оседает по высоте и мигает вместе с рамкой за 3 секунды до истечения карты
- Красная зона рисуется, только пока её пари лежит картой или активно; винная, без пульсации — она не телеграф атаки
- **ΔE-проверка** пар «карта / игрок / фишка / враг / телеграф / Крупье» — машинная (`npm run check:contrast`), CIEDE2000, два порога: 20 для одного слоя, 12 там, где различает форма ([GDD §21](GDD.md))
- Экран расчёта с near-miss: 5 секунд, пропуск после секунды и общий на всю команду, итоги живут всю паузу ([UX §4, §6](UX.md))
- Задержка перед первой волной — отдельное число (2.5 с): перед первой комнатой расчёта нет, и пауза, оплаченная его чтением, превращалась там в пустой экран ([GDD §5](GDD.md))

### Аудио [К]

- Подбор карты (шелест колоды, не «монетка»), «Забрать» (кассовый аккорд), появление Крупье, подброс, угасающий звон

### Данные [Д]

- Пари описываются JSON со схемой Zod, не кодом; исключения по схемам ввода — поле `excludeSchemes`, генератор сворачивает его в битовую маску ([content/bets.schema.md](../content/bets.schema.md))

### Тесты [Т]

- Каждое из шести пари: **засчитывается когда должно, проваливается когда должно**
- Прогресс `q` корректен для каждого
- «Забрать»: формула, `q=0` возвращает только кон
- Раскладка: количество, честность, персональные карты недоступны чужим, фильтр по схеме ввода владельца и по всему столу для общих
- Аппетит держится всю комнату и сбрасывается на её старте
- Крупье: подброс один за комнату, телеграф, уход через 3 с; выходов не больше двух, пауза между ними держится от ухода, жест не играется на пустой арене
- Инварианты догнали ставочную часть состояния: диапазоны схемы ввода и аппетита, валидность состояния и ссылки пари, неотрицательность кона и счётчика, жест и бюджет выходов Крупье ([DEVLOOP §6А](DEVLOOP.md))
- Визуальная регрессия: стресс-кадр в `stable()` — сетка средних цветов, эталон в `e2e/baselines` ([DEVLOOP §6](DEVLOOP.md))
- Декларативные сценарии пари: 28 штук в `tests/scenarios/bets`

### Проверка

```bash
npm run sim -- --scenario tests/scenarios/bets
npm run sim -- --runs 500 --bot greedy --json
npm run check:contrast
```

> **🚪 Ворота.** Плейтестер без подсказки берёт вторую карту и говорит «ещё разок». **Не-боевые экраны — меньше 20% времени комнаты.** Хотя бы одна смерть за сессию случается по дороге за картой: риск читается как свой, а не навязанный.

## 0.4.0 «Забег»

**Цель:** полный цикл от меню до итогов, и первый автобалансировщик.

### Структура забега [Я]

- Три этажа по восемь комнат, выбор из трёх дверей, шесть типов дверей ([GDD §5](GDD.md))
- Босс **Рулетка**: три фазы, встречная ставка, вращающаяся разметка колеса ([GDD §8.1](GDD.md))
- **Боссом всех трёх этажей версии остаётся Рулетка**, растущая запасом прочности по этажу. Однорукий бандит и Колода стоят в 0.7.0 и оттуда не двигаются, а ворота требуют полного забега 12–18 минут — то есть трёх этажей. Повтор босса назван заглушкой прямо здесь, чтобы он не оказался решением: этаж, кончающийся боссом, обязан быть проверен трижды, иначе кривая сложности теряет свои пики и проверять нечего
- Магазин: шесть апгрейдов, цены по формуле. Дверь «Лавка» — это бой, а после него прилавок: три предложения из шести, без повторов уже купленного. Каталог описан JSON со схемой Zod, как и пари ([content/upgrades.schema.md](../content/upgrades.schema.md))
- Дверь «Дар» — тот же прилавок бесплатно: один апгрейд из трёх, без ценников, и без экрана вовсе, когда давать уже нечего ([GDD §5](GDD.md))
- **Доля заведения** в конце этажа
- **Торг с Крупье** при нехватке: три варианта ([GDD §12А.2](GDD.md))
- **Ставка Крупье** — он ставит против игрока из своего кармана
- Долг и проклятия: не стакаются, обязательный трамплин после провала
- Экран итогов, смерть, победа

### Генерация [Я]

- Двенадцать шаблонов арен, каждый в четырёх отражениях: тождество, по горизонтали, по вертикали и оба сразу. Поворота на 90° нет и не будет — арена 16:9 ([GDD §16](GDD.md))
- Кривая сложности по бюджету угрозы
- Правило ввода новых врагов: не чаще одного типа за две комнаты

### Автобалансировщик [И]

- **Абстрактная модель комнаты** с калибровкой по полной симуляции
- Профили ботов: навык × стратегия
- Ограничители **G1–G10, G12–G14, D1–D10**
- Первый эволюционный поиск оптимума
- `npm run balance` с человекочитаемым отчётом

### Инфраструктура [Ф]

- Пост-мортемы 0.1.0, 0.2.0 и 0.3.0 в `docs/postmortems/` — просроченный за три версии процессный долг закрывается здесь и разом ([TECH §12А](TECH.md))
- i18n-словарь RU + EN, **хардкод строк запрещён линтером**
- Баг-репорт в один клик: реплей забега, версия и коммит сборки. Срабатывает и сам, на сломанном инварианте
- Миграции сохранений с версионированием

**Телеметрии в этой версии нет — ни своего ingest, ни Sentry**, и это решение, а не отставание. 0.4.0 играют разработчик, агент и те, с кем владелец играет вживую: телеметрия существует, чтобы узнать то, чего нельзя спросить, а у них можно спросить. При этом у проекта уже есть носитель сильнее событийного потока — детерминированный реплей: пятьдесят килобайт лога инпутов воспроизводят каждое взятое пари, каждую смерть и длительность каждой комнаты, и переигрываются headless-раннером теми вопросами, которых на момент записи никто не задавал. Событийный поток так не умеет.

Сроки остального: **Sentry — с 0.5.0**, первого выпуска, где спросить уже не у кого; **свой ingest — с 0.11.0**, как записано в [TECH §10](TECH.md) и в `.deploy-kit`. Третий слой проверки баланса ([ECONOMY §14](ECONOMY.md), [DIFFICULTY §12](DIFFICULTY.md)) приходит вместе с живыми игроками, то есть с 0.5.0, а не здесь: в 0.4.0 модель проверяется Monte-Carlo, ради которого и делается балансировщик.

### Тесты [Т]

- Босс: все переходы фаз, встречная ставка
- Долг: не стакается, трамплин обязателен
- Торг: все три варианта работают
- Миграции: каждая пара версий открывается
- Лавка: цены по формуле и среднее 45, три предложения из шести без повторов купленного, покупка не уводит кошелёк в минус, потолок двенадцати слотов, эффект работает в бою
- Декларативные сценарии лавки: 7 штук в `tests/scenarios/shop`, торга: 2 штуки в `tests/scenarios/floor`
- Дар: фишки не списываются, апгрейд ровно один, потолок слотов держится, за чужой дверью его нет, а когда давать нечего — нет и экрана. Декларативные сценарии: 3 штуки в `tests/scenarios/gift`
- Навигация геймпадом: каждый элемент достижим, нет тупиков фокуса
- Локализация: нет захардкоженных строк, все ключи во всех языках

### Проверка

```bash
npm run sim -- --runs 1000 --bot mixed --json
npm run balance
```

> **🚪 Ворота.** Полный забег 12–18 минут. Больше 60% плейтестеров начинают второй добровольно — **проверяется на соло-забеге**. ≥95% берут пари добровольно (синхронно с G6). Ограничители зелёные.

# Принципы

1. Ворота не пройдены — следующая версия не начинается. Особенно 0.2.0.
2. Каждая минорная версия — играбельная сборка с тегом и заметками.
3. Сценарии и golden-реплеи только накапливаются. Новая механика без сценария — незакрытая работа.
4. Публичный выпуск с 0.5.0: фидбек и вишлисты копятся заранее, а не в день релиза.
5. Контент режется, механики — нет.
6. Автоматика доказывает, что игра работает. Что в неё интересно играть — доказывает только человек.
