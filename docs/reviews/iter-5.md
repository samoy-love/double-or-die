## Проверено и не отъехало

Все тринадцать ревьюеров независимо перепроверили обе находки, закрытые в
iter-4, и подтвердили их устойчивость:

- **coach-pause** — `packages/client/src/renderer.ts:632-640`: `drawCoach`
  вызывается только при `settlementRows(s) === 0 && aceCardAt(s) < 0`.
- **Инверсия near-miss на Итогах** — `drawSummaryScreen`: строка
  `summary.nearmiss` по-прежнему берёт `100 - Math.round(progress)`.

Регресса нет ни там, ни там.

## Починено в этом заходе

**ТЗ-18. Дедуп `summaryLineCount` доведён до конца.**
`drawSummaryScreen` (`packages/client/src/renderer.ts`) по-прежнему считает
разбивку строк сам (ему нужен не только счётчик, но и текст каждой строки —
`fromBets`/`fromChips`/`fromBosses` с числами для `t(...)`), но теперь
подсчитывает фактически напечатанные строки (`visibleLines`) и в dev-сборке
(`__DEV_BUILD__`) сверяет их число с `summaryLineCount(s)`
(`packages/sim/src/run.ts:51`) — той же функцией, которую уже вызывает
`menuLayout.ts:57` для хитбокса кнопки «Ещё разок». Расхождение формул теперь
кричит в консоль дев-сборки, а не ждёт, пока кто-то заметит наезд кнопки на
текст глазами. Комментарий-докстрока над `summaryLineCount` (`run.ts:39-49`)
переписан — больше не утверждает, что находка не устранена.
Файлы: `packages/client/src/renderer.ts`, `packages/sim/src/run.ts`.

**ТЗ-19. Циклический импорт `spawn.ts` ↔ `progression.ts` разорван.**
Причина цикла была в том, что `spawn.ts` (бюджет и раскладка волны) сам звал
`advanceRoom` из `progression.ts` в конце `stepWaves`, а `progression.ts`
тянул `roomBudget`/`bossRoomBudget` обратно из `spawn.ts`. Решение —
из iter-4: `stepWaves` (`packages/sim/src/enemies/spawn.ts`) больше не
импортирует `progression.ts` и не вызывает `advanceRoom` — вместо этого
возвращает `boolean` («комната зачищена, шаг волны исчерпан»). Дирижирует
вызовом `packages/sim/src/enemies.ts:245` (`if (stepWaves(s)) advanceRoom(s);`)
— модуль, который и так ведёт полный тик врагов и уже реэкспортирует оба
подмодуля. Направление зависимости внутри `enemies/*` теперь одностороннее:
`progression.ts` → `spawn.ts`, без обратного ребра. Докстрока над `stepWaves`
объясняет решение и ссылается на риск, которого избежали.
Файлы: `packages/sim/src/enemies/spawn.ts`, `packages/sim/src/enemies.ts`.

Обе правки — точечные структурные изменения без изменения численных значений
`config.ts`, поэтому ре-бейзлайн golden-реплеев не требовался и не делался;
`npx vitest run` (535 тестов, включая все golden) остался зелёным без единой
правки эталонов.

## Не тронуто (крупные находки, вне объёма этого захода)

**ТЗ-20. Баланс — не тронут.** `npm run balance` не перепрогонялся заново в
рамках этого захода (не было явного запроса на баланс-таск, а числовые
предложения ревьюеров совпадают с iter-4 дословно — контрольный факт: ни
`config.ts`, ни `bets.ts` не менялись в этой итерации, значит новый прогон
дал бы те же 9 красных ограничителей, что и три раза подряд до этого).
Предложенные точные числа (`WEDGE.threat: 14 → 11`, `telegraphTicks: ticks(0.5)
→ ticks(0.65)`, отдельная выборка карты для `offerAceBet`, игнорирующая
конфликт с картами текущей раздачи) остаются в силе, см. §3 `iter-4.md`.
Правка отложена сознательно: она требует ре-бейзлайна golden-реплеев на трёх
ОС и записи в заметки версии — решение по объёму задачи, а не техническая
проблема.

**ТЗ-21. Разбор `renderer.ts` — не начат.** Файл — 5579 строк (было 5567 на
iter-4; рост — от правки ТЗ-18 этого захода, ожидаемо). План (menu screens →
run screens → gl/primitives → drawAce) не устарел, но это отдельная крупная
работа, не однострочная правка — вне объёма этого захода.

**Предложение (масштаб жестов Крупье).** ace-tone подтвердил кадр-в-кадр
сравнением: из шести жестов различимы уверенно только `thumbs-down` и `yawn`,
остальные (`applaud`/`ovation`, `fidget`/`turn-away`) визуально совпадают на
масштабе ~60×90px. Нужен приближённый (`zoom`) сценарий в `scripts/screens.ts`
или дебаг-оверлей — инструментальная задача, не однострочная правка,
остаётся предложением на следующий заход.

## Проверка

`npm run check && npx vitest run` — зелёные (535 тестов) после всех правок
этого захода. `config.ts` не менялся, поэтому golden-реплеи не пересчитывались
и не требовали ре-бейзлайна.

## Файлы, затронутые правками этого захода

- `packages/client/src/renderer.ts` — `drawSummaryScreen` сверяет число
  напечатанных строк с `summaryLineCount` в dev-сборке (ТЗ-18).
- `packages/sim/src/run.ts` — обновлена докстрока `summaryLineCount`.
- `packages/sim/src/enemies/spawn.ts` — `stepWaves` возвращает `boolean`
  вместо прямого вызова `advanceRoom`, импорт `progression.ts` убран (ТЗ-19).
- `packages/sim/src/enemies.ts` — вызывает `advanceRoom` по результату
  `stepWaves`.
