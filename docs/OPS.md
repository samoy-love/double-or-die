# Double or Die — телеметрия, observability и LiveOps

_Что видят администраторы, как принимаются решения по балансу, как всё это не стоит денег на старте._

---

## 1. Принципы

1. **Метрика существует, чтобы изменить решение.** Если по цифре мы ничего не сделаем — не собираем её.
2. **Игра полностью работает без бэкенда.** Нет сети — играем оффлайн, телеметрия копится локально и уходит позже. Падение аналитики не должно ронять игру никогда.
3. **Приватность по умолчанию.** Анонимные идентификаторы, никаких персональных данных, явное согласие, экспорт и удаление по запросу.
4. **Дёшево на старте.** До 10 000 игроков вся инфраструктура укладывается в бесплатные тарифы. Масштабируемся, когда появится выручка.

## 2. Схема потоков

```
   Клиент                    VPS (один сервер, Docker Compose)
┌──────────┐   батч 30 с   ┌─────────────────────────────────────────────┐
│ телеметр.│──────────────►│ Node (Fastify)                              │
│  буфер   │   gzip, ≤64КБ │  /ingest    — валидация схемы, rate limit   │
└──────────┘               │  /config    — remote config                 │
┌──────────┐               │  /boards    — лидерборды                    │
│  реплей  │──────────────►│  /replay    — очередь → replay-worker       │
└──────────┘               │  /signal    — сигналинг WebRTC (WebSocket)  │
┌──────────┐               │  АДМИНКА (§6)                               │
│  ошибки  │──► Sentry     ├─────────────────────────────────────────────┤
└──────────┘   (внешний    │ SQLite — события, таблицы, конфиг,          │
                free-tier) │          аудит-лог, логи реплеев            │
                           │          litestream → off-site бэкап        │
                           ├─────────────────────────────────────────────┤
                           │ coturn — TURN-релей       nginx — TLS       │
                           │ Grafana OSS (с 0.11.0) — дашборды из SQLite │
                           └─────────────────────────────────────────────┘
```

Вся серверная часть — один VPS владельца проекта ([TECH.md §3А](TECH.md)). До ~1000 одновременных игроков этого достаточно с большим запасом; события пишутся батчами, SQLite на таких объёмах скучает.

## 3. Схема событий

Единый конверт, версионированный. Схема лежит в `packages/shared` и валидируется и на клиенте, и на сервере — рассинхрон схемы невозможен.

```ts
type Event = {
    v: 1; // версия схемы
    ts: number; // клиентское время UTC
    sid: string; // сессия (случайный UUID)
    pid: string; // псевдонимный игрок: локально сгенерированный случайный UUID
    build: string; // версия + git SHA
    cfg: string; // версия remote config
    platform: 'win' | 'mac' | 'linux' | 'deck' | 'web' | 'ios' | 'android';
    name: string; // имя события
    props: Record<string, number | string | boolean>;
};
```

### Каталог событий

| Группа     | События                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Сессия     | `session_start` `session_end` (длительность, число забегов)                                                                     |
| Забег      | `run_start` (сид, режим, игроков) `run_end` (исход, этаж, комната, длительность, фишки) `floor_complete` `room_complete`        |
| **Пари**   | `bet_offered` (id, коэф.) `bet_taken` (id, тир) `bet_won` `bet_lost` (**near_miss_ratio** 0..1) `double_offered` `double_taken` |
| Экономика  | `chips_earned` (источник) `chips_spent` (сток) `shop_purchase` `debt_incurred` `rent_paid`/`rent_failed`                        |
| Бой        | `player_death` (враг, этаж, комната, HP-история) `boss_start` `boss_defeat` (время, попытки)                                    |
| Кооп       | `coop_join` `coop_leave` `revive` `ghost_bet` (за/против) `ping_used` `emote_used`                                              |
| Прогрессия | `unlock` `weapon_selected` `upgrade_taken`                                                                                      |
| Онбординг  | `tutorial_step` `first_bet_result` `first_death`                                                                                |
| Производ.  | `perf_sample` (fps p50/p1, GPU, разрешение) `load_time` `hitch` (кадр >100 мс)                                                  |
| Сеть       | `net_match_start` `net_rtt` `net_desync` `net_disconnect` `net_rollback_frames`                                                 |
| Настройки  | `setting_changed` (какая доступность включена — важно!)                                                                         |

**Семплирование:** `perf_sample` и `net_rtt` — 10% сессий. Всё игровое — 100% (объём смешной).

## 4. Дашборды Grafana

Шесть панелей, каждая отвечает на конкретный вопрос.

### 4.1 «Здоровье» (смотрят ежедневно)

Онлайн сейчас · DAU/WAU/MAU · **crash-free sessions %** · частота ошибок · p95 времени загрузки · доступность бэкенда · 5xx на эндпоинтах.
**Алерты:** crash-free < 99% · ошибки ×3 к базовой линии · 5xx > 1%.

### 4.2 «Воронка и удержание»

Установка → первый запуск → **завершил первую комнату** → **сделал первую ставку** → завершил первый забег → вернулся на второй день.
D1/D7/D30 удержание · когорты по неделям установки · распределение сессий в день · точка выхода (на какой комнате бросают).
**Главный вопрос:** где именно теряем новичка.

### 4.3 «Экономика и баланс» ← сердце игры

- **Take rate по каждому пари** (как часто берут) и **win rate** (как часто выигрывают).
- **Распределение near-miss** — какие пари проваливаются «почти». Пари с высоким near-miss и средним win rate — идеальные, их надо тиражировать.
- Доминация тира кона: % выбора Скромно / Нормально / **По-крупному**. Если верхний тир выбирают >70% опытных игроков — экономика сломана.
- Приток и сток фишек по источникам, медианный кошелёк по комнатам.
- Частота долга, доля выхода из долга.
- Take rate «Удвоим?» и его win rate.
- Популярность апгрейдов (никто не берёт = мёртвый контент).

### 4.4 «Сложность»

Win rate по этажам · смерти по врагам и комнатам · **тепловые карты смертей на аренах** · время боя по комнатам · win rate боссов и число попыток · распределение достигнутого этажа.

### 4.5 «Производительность»

FPS p50/p1 в разрезе GPU, платформы, разрешения · доля сессий ниже 50 FPS · **отдельная панель Steam Deck** · длительность загрузки · частота хитчей.

### 4.6 «Сеть»

Доля кооп-сессий · размер лобби · распределение RTT · **desync rate** (цель: < 0.1% матчей) · disconnect rate · кадры отката p95 · успешность миграции хоста.

### 4.7 «Кооп-социология» (уникально для нашей игры)

Доля забегов с 2/3/4 игроками · частота ставок на напарника · **частота ставок Духа против живых** и корреляция с продолжением сессии (весело или токсично?) · частота воскрешений · провалы доли заведения · **доля забегов с нулём взятых пари** (если растёт — механика принуждения не работает).

## 5. Remote config и фиче-флаги

Балансные числа живут на сервере, не в билде.

```jsonc
{
    "version": 42,
    "bets": { "no_damage": { "mult": 3.0, "enabled": true } },
    "economy": { "room_payout_base": 8, "rent_floor1": 60 },
    "waves": { "threat_base": 40, "threat_growth": 0.35 },
    "flags": { "ghost_bets_against": true, "versus_online": false },
}
```

- Клиент тянет при старте, кеширует, **при недоступности использует зашитый в билд дефолт**.
- **Конфиг разделён на два класса** ([TECH.md §8.3](TECH.md)): _симуляционный_ (влияет на детерминизм — коэффициенты, цены, волны) выкатывается только целиком, всем сразу и на границе суток; _прикладной_ (тексты, семплирование, объявления, косметические флаги) допускает свободный раскат 5% → 25% → 100%.
- **Почему так:** постепенный раскат симуляционных чисел разделил бы игроков на несовместимые группы, и друзья не смогли бы зайти в одно лобби. Для кооп-игры это отказ продукта.
- **A/B-тесты баланса — последовательные, а не параллельные:** сравниваем версии конфига во времени. Медленнее, зато мультиплеер цел.
- Версия симуляционного конфига входит в хеш совместимости лобби; дейли фиксирует её на сутки.
- Откат — мгновенный, в один клик, отрепетирован до релиза.
- Любое изменение логируется в неизменяемый аудит-лог: кто, что, когда, с какого адреса.
- Изменение проходит серверную валидацию схемы: сломанный конфиг не должен физически дойти до клиентов.

## 6. Админ-панель

Внутреннее веб-приложение на том же VPS. Доступ — **не из публичного интернета**: Tailscale/WireGuard (предпочтительно) или Basic-auth + TOTP за nginx. Роли: `viewer` / `designer` / `admin` — формальность при одном человеке, но пишутся сразу, чтобы аудит-лог имел смысл.

| Раздел                     | Возможности                                                                                                                                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Обзор**                  | живой онлайн, ключевые метрики за 24 ч, активные алерты                                                                                                                                                       |
| **Конфиг**                 | редактор баланса со схемой и валидацией, раскат по процентам, история версий, откат в один клик                                                                                                               |
| **Флаги**                  | включение/выключение фич, таргетинг по платформе и версии                                                                                                                                                     |
| **Лидерборды**             | дейли и еженедельные, модерация: снять результат, забанить Steam ID (таблицы живут в пространстве Steam ID; `pid` — только телеметрия, пространства не связываются), посмотреть реплей подозрительного забега |
| **🎬 Просмотрщик реплеев** | ввести код забега → посмотреть его целиком с перемоткой. Работает, потому что симуляция детерминирована                                                                                                       |
| **Игрок**                  | по анонимному ID: история забегов, устройство, версии, крэши. Для поддержки                                                                                                                                   |
| **Контент**                | редактор пари, врагов, апгрейдов, барков Туза с валидацией схемы                                                                                                                                              |
| **LiveOps**                | расписание еженедельных мутаторов, ручная переустановка дейли-сида, объявления в главном меню                                                                                                                 |
| **Приватность**            | обработка запросов на экспорт и удаление данных                                                                                                                                                               |

**Просмотрщик реплеев — недооценённая вещь.** Дизайнер может посмотреть, как реально играют сотня случайных игроков: где мечутся, какие пари берут, где умирают. Это заменяет дорогие лабораторные плейтесты. Поддержка может воспроизвести любой баг-репорт точно.

## 7. Приватность и соответствие

- **Согласие** на первом запуске: понятный экран, «Играть без телеметрии» — полноценная опция, не тёмный паттерн. Крэш-репорты и аналитика — раздельные переключатели.
- **Данные псевдонимные, и мы честны в этом.** `pid` — случайный UUID, генерируемый локально; стабильный идентификатор с поведенческой историей — это персональные данные по GDPR (псевдонимизация ≠ анонимизация), поэтому режим обработки — минимизация, а не отрицание. Steam ID **не** связывается с `pid` (лидерборды — отдельное пространство). Свой `pid` игрок видит в настройках — для запросов экспорта и удаления.
- **IP:** для rate limit держится в скользящем окне в памяти, в события не пишется; геолокация до страны — на лету. В Sentry `sendDefaultPii = false` — фильтр `beforeSend` не спасает от серверного сбора IP самим SDK.
- **Субпроцессоры:** Sentry (ЕС-регион, DPA) — единственный внешний. Всё остальное — на собственном VPS, и это резко упрощает приватность: удаление по запросу — одна транзакция в SQLite.
- **Хранение:** сырые события 180 дней, агрегаты бессрочно.
- **GDPR/CCPA:** экспорт и удаление по запросу через админку, срок ответа 30 дней.
- **Дети:** игра не для детей до 12, возрастной гейт не требуется, но COPPA-safe по построению (нет персональных данных).
- Политика приватности и EULA — на сайте и в игре, ссылки на странице Steam.

## 10. Ритуалы работы с данными

- **Ежедневно (5 мин):** «Здоровье» + алерты.
- **Еженедельно (30 мин):** воронка, удержание, экономика. Одна гипотеза → один эксперимент в конфиге.
- **После каждого релиза:** сравнение до/после по crash-free, FPS, D1, take rate.
- **Перед каждым балансным патчем:** прогон Monte-Carlo на новых числах, затем выкладка новой версии симуляционного конфига целиком (по процентам он не раскатывается — [TECH.md §8.3](TECH.md)) и сравнение метрик с прошлым периодом.
